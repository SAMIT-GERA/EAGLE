# Uploaded-document preflight (v1)

This is a local, deterministic inspection boundary, not proof of supplier authenticity. The original upload digest attests only to bytes held by this process. `DP-P001` always reports that independent supplier-origin verification is unavailable.

Binding two confirmed documents triggers inspection of both original files and the confirmed normalized records. The task binding, document IDs, original SHA-256 digests, normalized SHA-256 digests, and inspection version are retained in process-local assessment state. A later run requires `ALLOW` for both documents and rechecks those digests before any coordinator or model call. `REVIEW`, `BLOCK`, a missing assessment, an expired session, and scanner failure all deny operational disclosure. There is no automatic reviewer release in v1; an operator must use a new upload session for corrected documents. Confirmation of extracted fields is not preflight clearance.

The inspector scans at most 64,000 characters per document and blocks larger text. It uses bounded local rules: `DP-I001` role spoofing, `DP-I002` instruction override, `DP-I003` grant/policy manipulation, `DP-I004` outbound exfiltration, `DP-I005` tool/deletion/credential instructions, `DP-I006` encoded-instruction indicators, `DP-S001` email, `DP-S002` phone, `DP-S003` credential/token, `DP-S004` financial account, `DP-S005` personal/private-business indicator, `DP-D001` inspection-size limit, `DP-D002` digest integrity, `DP-D003` missing/nested source fields, `DP-D004` source/confirmed mismatch, `DP-D005` arithmetic mismatch, `DP-D006` currency mismatch, `DP-D007` duplicate keys, and `DP-P001` unknown authenticity. Findings contain only rule IDs, fixed explanations and redacted field locations; matched text is never copied into a finding.

For ordinary uploaded comparisons, the coordinator gives Gemini only the confirmed business-field projection. Uploaded `documentText` and excerpts are removed from Planner and Reviewer input; raw bytes remain available only to the local scanner and integrity bridge. The gateway still makes every tool authorization decision. The authenticated `GET` and `POST /api/uploads/sessions/:sessionId/tasks/:taskId/preflight` endpoints require the matching upload capability and operator PIN. POST reruns inspection; neither endpoint grants an override.

The separately labeled `POST /api/security/controlled-adversarial-test` endpoint uses only synthetic fixtures, requires the operator PIN, and creates a unique read-only task grant. It uses the existing coordinator and gateway. Its `modelResistance` field deliberately says `not_established_by_gateway`; gateway enforcement is reported independently. This mode never releases quarantined uploads and has no side-effecting tool permission.

Limitations: regex rules can miss novel or obfuscated attacks and can flag benign text. Personal-data and account detection are indicators, not comprehensive PII classification. Provenance remains unknown without external verification. Assessment and upload state vanish on restart; the durable audit store does not make preflight persistent. No REVIEW release workflow exists yet.
